# Contribution Guidelines

## What belongs here

- Open-source projects built for Scouting America units, leaders, Scouts, or families.
- Projects with a public source repository and an [OSI-approved license](https://opensource.org/licenses).
- Projects that are maintained and documented.

## What does not belong here

- Official Scouting America websites, apps, or publications, including PDFs.
- Closed-source or proprietary software, even if it's free.
- Projects that are archived, abandoned, or have no documentation.
- Council or unit websites, unless the site's source is published as a reusable template.

## Adding an entry

- Search previous suggestions before making a new one to avoid duplicates.
- Add one item per pull request.
- Add the entry at the bottom of the most relevant category.
- Use this format: `- [Project Name](https://link-to-project) - Short description.`
- Keep descriptions short and objective. Start with an uppercase character and end with a period.
- Use the project's official name and capitalization.
- Use a descriptive pull request title, such as `Add Project Name`.
- Check your spelling and grammar.
- Make sure your text editor strips trailing whitespace, and don't hard-wrap lines.

## Updating your pull request

Sometimes a maintainer will ask you to edit your pull request before it's merged. If you're not sure how, read [this guide](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md).
